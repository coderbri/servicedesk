# ServiceDesk API reference

This guide documents the implemented service-request endpoints. Examples use `http://localhost:8080`; start the application with `./gradlew bootRun` and configure the database connection first. The API routes are under `/api/requests`.

Requests and responses use JSON. Send `Content-Type: application/json` when a request has a body. No authentication or pagination behavior is implemented or required by these endpoints.

## Shared data rules

### Request fields

`POST /api/requests` and `PUT /api/requests/{id}` accept these fields:

| Field | Type | Rules |
| --- | --- | --- |
| `title` | string | Required; must not be empty or whitespace only; maximum 150 characters. |
| `description` | string | Required; must not be empty or whitespace only; maximum 2,000 characters. |
| `priority` | string enum | Required; one of `LOW`, `MEDIUM`, `HIGH`. |
| `status` | string enum | Required for updates only; one of `OPEN`, `IN_PROGRESS`, `RESOLVED`, `CLOSED`. New requests start as `OPEN`. |

The limits and required fields come from the create and update DTO validation annotations. Enum values are case-sensitive Java enum names.

### Response representation

A successful create, get-one, or update response contains these fields:

```json
{
  "id": 42,
  "title": "Laptop Wi-Fi issue",
  "description": "Cannot connect to the office network.",
  "status": "OPEN",
  "priority": "HIGH",
  "createdAt": "2026-11-03T14:25:30"
}
```

This is a representative example. `id` is generated by persistence, and `createdAt` is set when the record is first persisted, so their values vary. The timestamp is a `LocalDateTime` JSON value and has no timezone offset in this representation. Updates preserve the existing ID and creation time.

### Status transitions

An update may keep the current status or move exactly one step forward:

| Current status | Allowed next status |
| --- | --- |
| `OPEN` | `OPEN`, `IN_PROGRESS` |
| `IN_PROGRESS` | `IN_PROGRESS`, `RESOLVED` |
| `RESOLVED` | `RESOLVED`, `CLOSED` |
| `CLOSED` | `CLOSED` |

A backward move, skipped step, or move out of `CLOSED` returns `400 Bad Request`.

## `POST /api/requests`

Create a service request. The server assigns its initial status (`OPEN`), ID, and creation time.

### Request

```json
{
  "title": "Laptop Wi-Fi issue",
  "description": "Cannot connect to the office network.",
  "priority": "HIGH"
}
```

### Success

`201 Created` with the created request representation shown above.

### Errors

- `400 Bad Request` when a required field is missing/null, blank, too long, or a supplied enum value cannot be converted. The precise response body is framework-generated; see [Error response behavior](#error-response-behavior).

### cURL

```bash
curl -i -X POST http://localhost:8080/api/requests \
  -H 'Content-Type: application/json' \
  -d '{"title":"Laptop Wi-Fi issue","description":"Cannot connect to the office network.","priority":"HIGH"}'
```

## `GET /api/requests`

Retrieve all service requests. This endpoint returns the repository's full result list; there are no pagination parameters implemented.

### Success

`200 OK` with a JSON array of request representations. When there are no saved requests, the result is an empty array (`[]`). For example:

```json
[
  {
    "id": 42,
    "title": "Laptop Wi-Fi issue",
    "description": "Cannot connect to the office network.",
    "status": "OPEN",
    "priority": "HIGH",
    "createdAt": "2026-11-03T14:25:30"
  }
]
```

Array contents and order depend on the records returned by persistence; no ordering guarantee is defined by this controller or service.

### cURL

```bash
curl -i http://localhost:8080/api/requests
```

## `GET /api/requests/{id}`

Retrieve one service request by its numeric ID.

### Success

`200 OK` with a single request representation.

### Errors

- `404 Not Found` when no request exists for the supplied ID. The service raises this status with the reason `Service request not found: {id}`.
- A non-numeric path value cannot be bound to the `Long` ID parameter and is rejected by Spring MVC; its response body is not customized by this application.

### cURL

```bash
curl -i http://localhost:8080/api/requests/42
```

## `PUT /api/requests/{id}`

Replace all editable request fields for an existing request. The JSON body must include `title`, `description`, `priority`, and `status`. The ID and `createdAt` are retained.

### Request

```json
{
  "title": "Laptop Wi-Fi issue",
  "description": "Network adapter reset; connection restored.",
  "priority": "MEDIUM",
  "status": "IN_PROGRESS"
}
```

### Success

`200 OK` with the updated request representation. This example assumes the request was previously `OPEN` and uses the allowed `OPEN` → `IN_PROGRESS` transition.

### Errors

- `400 Bad Request` for missing, null, blank, or too-long required fields, invalid enum values, or a status transition that violates the lifecycle rules.
- `404 Not Found` when the ID does not identify an existing request. The service raises this status with the reason `Service request not found: {id}`.

### cURL

```bash
curl -i -X PUT http://localhost:8080/api/requests/42 \
  -H 'Content-Type: application/json' \
  -d '{"title":"Laptop Wi-Fi issue","description":"Network adapter reset; connection restored.","priority":"MEDIUM","status":"IN_PROGRESS"}'
```

## Status code summary

| Endpoint | Success | Implemented error outcomes |
| --- | --- | --- |
| `POST /api/requests` | `201 Created` | `400 Bad Request` for request validation or JSON-to-DTO conversion failures. |
| `GET /api/requests` | `200 OK` | No endpoint-specific error outcome is defined in the controller/service. |
| `GET /api/requests/{id}` | `200 OK` | `404 Not Found` if absent; invalid ID conversion is rejected by Spring MVC. |
| `PUT /api/requests/{id}` | `200 OK` | `400 Bad Request` for validation/conversion or invalid status transition; `404 Not Found` if absent. |

Other failures, such as an unavailable database, are not translated into API-specific status/body behavior by these endpoints and are outside this reference's guaranteed contract.

## Error response behavior

The application does not define a `@ControllerAdvice` or endpoint-specific exception response DTO. The service uses Spring's `ResponseStatusException` for a missing record and an invalid status transition, while request validation and JSON conversion are handled by Spring MVC. Therefore, the HTTP status outcomes described above are implemented, but clients should not depend on one exact JSON error-body schema or message format. Error details and body shape can depend on Spring Boot configuration and framework defaults.
